# Speech zero-watermarks under neural codecs and voice conversion

Code, clip lists and result files for the manuscript

> B. Bakhtiari and H. R. J. Nikzat, "Neural Codecs and Voice Conversion Reveal Two Weaknesses of Speech
> Zero-Watermarks", submitted to *Circuits, Systems, and Signal Processing*, 2026.

A zero-watermark does not change the audio. The owner computes a binary fingerprint F of the recording and
registers K = F XOR W, where W is a logo or an owner identifier. This repository tests how well such fingerprints
survive 32 attacks: classical edits, Opus, time misalignment, two neural codecs (EnCodec and the Descript Audio
Codec, DAC) and voice conversion (kNN-VC and SpeechT5). The tests cover four fingerprint families (DWT-DCT, a
Philips-style band-energy fingerprint, segment MFCCs and a hash of WavLM features) and two published schemes that
we reimplemented from their papers (Chen and Zhu, 2008; Salayani, Bakhtiari and Ghafarian, 2023).

Every number and figure in the manuscript is computed from the files in `results/`.

## Layout

```
zwm/        the package
            schemes.py   fingerprint families, candidate pool, attack-aware bit selection, XOR registration
            chenzhu.py   reimplemented Chen-Zhu (2008) scheme
            salayani.py  reimplemented Salayani et al. (2023) supervised scheme
            attacks.py   classical attacks, Opus, misalignment, EnCodec, DAC, kNN-VC
            codes.py     repetition, BCH(1023, 76) and polar(1024, 76) codes for the owner identifier
            metrics.py   BER, thresholds at a false-accept rate, true-positive rate, AUC
            audio.py     loading, resampling, alignment
scripts/    one script per experiment (see below)
tests/      pytest checks of the fingerprints, attacks, metrics, codes and the Chen-Zhu reimplementation
data/       manifest.csv: the 478 clips (80 training, 398 test) as LibriSpeech utterance ids
            manifest_80.csv: the 80-clip test subset used for the speech-recognition check and the search verifier
results/    every result table (CSV/JSON) and the fingerprints of all clips under all attacks (fingerprints.npz)
figures/    the two figures of the manuscript
```

`results/fingerprints.npz` holds the bits of every scheme for every clip under every attack, so the tables can be
recomputed from it without regenerating any audio.

## Data and models you need

| What | Where it comes from | Used by |
|---|---|---|
| LibriSpeech dev-clean, test-clean, test-other | https://www.openslr.org/12 | clips and external impostors |
| CMU ARCTIC, voices bdl, rms, jmk, awb, ksp, slt, clb | http://festvox.org/cmu_arctic/ | same-sentence test |
| kNN-VC code and checkpoints | https://github.com/bshall/knn-vc (clone to `../ext/knn-vc` or set `KNNVC_REPO`) | voice conversion |
| EnCodec 24 kHz, DAC 16 kHz | downloaded by the `encodec` and `descript-audio-codec` packages on first use | codec attacks |
| WavLM-Base-Plus, SpeechT5 VC and HiFi-GAN, Whisper base.en | Hugging Face model hub, downloaded on first use | WavLM-LSH, second converter, speech recognition |
| CMU ARCTIC x-vectors | the speaker-embedding files commonly used with SpeechT5 (pass their folder with `--xvec`) | SpeechT5 target voices |
| FFmpeg with libmp3lame and libopus | system package | MP3 and Opus attacks |

No audio is included. The clip lists name every utterance, and the attacked copies are regenerated by the scripts.

## Reproducing the results

Everything runs on a CPU. Install the packages in `requirements.txt` (the pinned versions are the ones the results
were produced with), then run, from the repository root:

```bash
python scripts/prepare_data.py   --librispeech /path/LibriSpeech --out data
python scripts/extend_test.py    --librispeech /path/LibriSpeech --per-speaker 20
python scripts/run_attacks.py    --librispeech /path/LibriSpeech --data data --cache cache
python scripts/run_speecht5_vc.py --xvec /path/to/xvectors --librispeech /path/LibriSpeech
python scripts/build_impostors.py --librispeech /path/LibriSpeech --out results
python scripts/run_eval.py       --data data --cache cache --out results
python scripts/run_chenzhu.py    --librispeech /path/LibriSpeech
python scripts/tune_salayani.py  && python scripts/run_salayani.py
python scripts/run_same_text.py  --arctic /path/to/arctic
python scripts/run_search.py     --schemes classical && python scripts/run_search.py --schemes wavlm --groups desync
python scripts/run_search_far.py --schemes classical --librispeech /path/LibriSpeech
python scripts/run_search_far.py --schemes wavlm     --librispeech /path/LibriSpeech
python scripts/sample_shift.py   && python scripts/dac_realign.py
python scripts/run_codes.py
python scripts/run_quality.py    && python scripts/run_wer.py
python scripts/time_extractors.py
python scripts/make_figures.py   --results results --out figures
pytest -q
```

Each script states its inputs and outputs in its docstring. `scripts/extend_fingerprints.py`
was used to extend an earlier 160-clip run to the current 478 clips without recomputing the clips it already had; a
fresh run does not need it.

The slowest steps are the attacks (DAC and voice conversion), the Salayani scheme (one SVM per training attack per
clip) and the search verifier at a 0.01% false-accept rate (121 offsets per pair).

## Notes on the two reimplemented schemes

Both are reimplemented from their papers, not from the authors' code, and fix choices that the papers leave open.
Section 3.2 of the manuscript lists these choices: for Chen-Zhu the sampling rate, the number of values kept per
frame and the cumulant estimator; for Salayani et al. the SVM hyper-parameters (chosen on training clips by
`scripts/tune_salayani.py`) and the binarization rule. Eq. 5 of Salayani et al. as printed sets every bit of an
original recording to 1, because the feature it thresholds is a magnitude; this is evidently a typo. The results use
the rule as printed; `ZWM_SZ_RULE=mean` runs the scheme with a threshold at the mean of each clip's features instead.
